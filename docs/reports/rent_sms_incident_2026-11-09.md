# 2026-11-09 미납 목록 및 문자 발송 조사

## 확인 범위

첨부 화면과 로컬 코드/커밋, 운영 DB의 읽기 전용 SELECT를 대조했다. 운영 데이터 변경, 배포, 실제 문자 발송은 하지 않았다.

## 확정된 원인

`7719ddd`에서 `app/routes/admin.py:get_rent_management_contracts`의 조회 대상을 active에서 active/terminate_requested/terminated로 확대했다. 계약 기간의 월 겹침만 검사하므로 종료 상태이면서 end_date가 2099년으로 남은 레거시 계약도 현재 월 목록에 포함된다. 계약이 실제로 재활성화된 현상은 아니다.

## 문자 조사

- 운영 로그 1188: 2026-11-09 09:20:58, 계약 145, PAYMENT_OVERDUE_STAGE1, SENT(Aligo). 공급자 접수 성공이며 실제 단말 수신 확인을 의미하지 않는다.
- PAYMENT_OVERDUE_STAGE1 템플릿은 활성 상태다.
- 계약 221은 수신 번호가 없다. 현재 `SmsService.send_sms`는 이 경우 `Receiver phone number missing`을 반환하고 로그를 만들기 전에 종료한다. 잘못 노출된 계약에서 발송 실패가 발생할 수 있는 확정된 경로다.
- 첨부에는 문자 실패 팝업/실패 대상/서버 오류가 없어 최초 문자 실패를 위 경로로 단정할 수 없다. 정다빈 계약에는 번호가 있어 번호 누락으로 설명되지 않는다.
- 최신 로그 및 조회된 실패 이력에서는 당일 공급자 실패 기록이 확인되지 않았다. 로그가 없는 검증 단계 실패/서버 예외는 배제할 수 없다.

## 수정 시 지켜야 할 조건

1. 종료일 2099년만으로 종료 계약을 현재 월 청구 대상으로 판단하지 않는다. 종료 계약의 과거 납부 내역 조회와 당월 실제 퇴실 계약 조회는 보존해야 한다.
2. 실제 퇴실일이 확인되지 않은 레거시 종료 계약의 날짜를 임의 추정해 운영 DB에 쓰지 않는다.
3. 월세 조회와 수동 PAYMENT 문자 발송에서 같은 계약 유효성 규칙을 적용한다.
4. 전화번호 누락 등 공급자 호출 이전 실패도 운영자가 추적할 수 있게 한다.
5. 최초 문자 실패 원인의 확정에는 실패 대상과 당시 응답 또는 서버 로그가 추가로 필요하다.

## 후속 수정

사용자의 진행 지시에 따라 로컬 코드에 수정했다. 운영 배포 및 운영 데이터 변경은 아직 수행하지 않았다.

- 공통 `rent_period_filter`를 월세 관리, 월별 납부 목록, 납부 상태 변경, 수동 PAYMENT 문자에 적용했다.
- 종료 계약은 확인된 퇴실 적용일을 우선 사용하고, 없으면 유한한 계약 종료일로 조회 기간을 판단한다. 퇴실일 없이 종료일만 2099년인 종료 계약은 청구 대상에서 제외한다. 실제 퇴실일은 추정하지 않으며 기존 납부 데이터도 변경하지 않는다. 이 레거시 계약의 과거 월세 목록 복원에는 실제 퇴실일 확인이 필요하다.
- 활성 무기한 계약과 퇴실 신청 중인 계약의 기존 월세 처리는 유지한다.
- 전화번호가 없거나 숫자가 전혀 없는 수신 번호는 공급자를 호출하지 않고 한국어 오류 및 FAILED 이력을 남긴다. 번호 보완 후 재시도할 수 있다.
- 격리 SQLite/API 회귀 테스트 28개 통과. 문제 계약 재현, 조회 두 경로, 직접 문자·납부 요청 차단, 당월/과거 종료 계약 유지, 활성 무기한 계약 유지, 번호 누락 로그와 재시도를 포함한다.
- 인접 퇴실 신청·승인·정산 테스트 24개도 통과했다. 총 52개 통과이며 변경 파일의 `git diff --check`도 통과했다.
- 운영 DB에 새 조건을 SELECT로만 대조: 141·221 제외, 정상 활성 263 유지, 실제 11월 1일 종료 계약 266 유지. 기존 11월 월세 목록과 비교했을 때 제외되는 계약은 정확히 141·221 두 건이다.

최초 문자 실패 건 자체의 원인 확정 및 실제 외부 문자 수신 검증은 미완료다. 이번 수정으로 확인된 번호 누락 실패를 추적할 수 있게 했다.

## 최초 문자 신고 추가 조사

사용자는 카카오톡으로 전달받았으며 실패 대상이나 오류 문구를 알지 못한다고 확인했다. 따라서 전달된 신고와 특정 발송 건을 동일한 것으로 단정할 수 없다.

운영 DB의 2026-11-09 전체 문자 이력은 1건이다.

- 로그 1188 / 계약 145 / 삼성점 11호 김채현 / PAYMENT_OVERDUE_STAGE1
- 수동 발송 키의 force 표식 확인. 등록 시각 2026-11-09 09:20:58.
- 공급자 메시지 ID 1499345693.
- 알리고 공식 결과 조회 API `sms_list`로 직접 조회: result_code=1, 상세 ID 9772539769, sms_state=발송완료, reg_date/send_date 모두 2026-11-09 09:20:58.
- 알리고 `list`를 20261109 하루 범위로 조회: 위 메시지 1건, sms_count=1, fail_count=0, next_yn=N.
- 조회만 수행했으며 문자 발송/재발송이나 운영 DB 변경은 수행하지 않았다.

결론: 신고 직전 확인되는 유일한 발송 건은 공급자 상세 결과상 발송완료다. 이를 문자 전송 실패로 설명할 수 없다. 사람이 실제 읽었는지/메시지함에서 보았는지를 확인한 것은 아니다. 다른 계약을 눌렀거나 발송 API 진입 전에 실패한 건이라면 기존 SMS 이력에 남지 않을 수 있다. 실패 대상/당시 HTTP 응답/서버 또는 브라우저 로그가 없는 현재 자료만으로 최초 신고의 정확한 원인을 확정할 수 없다. 김찬미 8호 번호 누락을 최초 실패 원인으로 단정하지 않는다.
