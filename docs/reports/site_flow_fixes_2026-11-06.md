## 로컬에서 확인

- 주소: [격리 로컬 미리보기](http://127.0.0.1:5057)
- 관리자: `admin@local.test` / `Local-preview-123!`
- 입주자: `tenant@local.test` / `Local-preview-123!`
- 쿠폰: `LOCAL10K`
- 실행 파일: [run_local.py](C:/workspace/Eroom-Studio/run_local.py). 일반 `run.py`는 운영 환경 설정을 읽으므로 이번 검증에 사용하지 않았습니다.

`run_local.py`는 `DATABASE_URL`을 사용하지 않고 `instance/local-preview.sqlite3`만 사용합니다. 별도 미리보기 서명 키를 사용하며, 실제 문자·카카오 인증·자동 배치를 차단합니다. 미리보기 업로드도 `instance/local-uploads`에 분리합니다. [상태 확인](http://127.0.0.1:5057/health)에서 `mode=local`, `database_backend=sqlite`, `sms_enabled=false`, `scheduler_enabled=false`를 확인할 수 있습니다.

브라우저 검증 과정에서 만든 계약·서명·퇴실·답변 데이터가 로컬 DB에 남아 있습니다. 운영 자료를 복사하거나 수정한 데이터가 아닙니다.

## 배포와 검증의 범위

테스트는 운영 DB에 연결하지 않는 `testing` 모드와 메모리 SQLite에서 실행했습니다. 기존 테스트 중 `development` 설정을 읽던 파일도 `testing`으로 전환했습니다. API/정산/이미지/마이그레이션 회귀 테스트와 관리자 JS 테스트를 실행했고, 실제 브라우저 검사에서는 신청·쿠폰·관리자 승인·캔버스 서명·퇴실 갱신·답변 조회·세션·로그인 복귀·모바일을 확인했습니다.

운영 MySQL migration 및 실제 외부 문자/카카오 전달은 실행하지 않았습니다. `b6e1106flowfix`는 컬럼·테이블을 확장하고 기존 금액을 비어 있는 새 필드로만 복사하며, 기존 컬럼을 삭제하지 않습니다. downgrade도 추가 스키마/데이터를 유지하여 앱 코드 롤백을 지원합니다. 운영 적용 전에는 실제 스키마와 백업을 대조해야 하며, 이 보고서는 운영 적용 완료를 뜻하지 않습니다.
